MTR OmegaT 工作流整合与目录清理计划

北极星：仓库中只保留一套正式的中文源文件、一套当前 OmegaT 工作区、一个可双击的入口和必要的审校记录；开始审校与完成回写使用同一个入口，人工翻译仍在 OmegaT 内完成，术语告警继续只作参考而不阻塞发布。

复用现有能力当前导出、回写、验证、构建、批注归档和审校进度逻辑已完整，不重写解析器。
只解决真实缺口补上“准备项目”和“查看进度”的入口，并停止永久累积候选目录。
本计划不执行删除先由用户批准精确路径；执行清理前必须关闭 OmegaT。

1. 范围、非目标与边界

范围

  • 识别并删除 OmegaT 试验期间产生、且不再被正式流程引用的文件。
  • 把“生成 OmegaT 项目 → 人工审校 → 预览/确认 → 写回 YAML → 测试 → 生成 dist → 登记进度”整理为一个双击入口。
  • 保留现有稳定 ID、PO 格式、术语库、批注归档和审校台账。

非目标

  • 不自动操作 OmegaT 编辑界面，也不替代人工审校。
  • 不把 LLM 语义审计嵌入确定性发布流程。
  • 不修改 YAML/输出 JSON 的数据结构，不引入数据库、GUI 框架或新依赖。
  • 不把术语审计改成阻塞条件。
  • 不处理官方英文版本更新；该职责继续由现有 official-update/reference 流程承担。

假设与权限边界

  • 正式中文源以 src/mtr/<current-version>/*.yaml 为准，dist 只能由构建器生成。
  • OmegaT 当前项目为 outputs/omegat-mtr-full，其中 omegat/project_save.tmx 是尚未写回内容与批注的重要工作数据。
  • 清理是不可逆删除；只有用户批准清单且 OmegaT 已关闭后才执行。

2. 已审阅的依据

  • README.zh-CN.md：当前日常、首次导出、手动回写和状态流程。
  • 审校助手.cmd：当前唯一双击入口，但只执行完成阶段。
  • mtr_pipeline/review_workflow.py：预览、候选验证、确认、写回、测试、术语审计、dist 构建和审校登记。
  • mtr_pipeline/omegat.py：从正式 YAML 生成 17 个 PO 和 OmegaT 项目。
  • mtr_pipeline/omegat_import.py：稳定 ID 校验、最小差异写回与隔离候选。
  • mtr_pipeline/review_status.py：批注解析、审校台账和 stale 检测。
  • mtr_pipeline/terminology.py：非阻塞术语审计。
  • tests/test_review_workflow.py 及相关 OmegaT 测试：当前安全门和回归覆盖。
  • 实际文件盘点、Git 跟踪状态、忽略目录和目录体积；未使用外部网络资料。

手工运行导出命令→ OmegaT 人工审校→ 创建已译文档→ 双击审校助手→ YAML + 测试 + dist + 台账

5. 推荐的统一工作流

推荐：保留 审校助手.cmd 这个唯一入口，把它扩展为三个选项；不新增第二个启动器、不新增配置文件、不引入依赖。
MTR 中文翻译工作流

1. 准备或继续 OmegaT 审校
2. 完成审校并生成最终文档
3. 查看审校进度
q. 退出

选项 1：准备或继续 OmegaT 审校

  1. 从 src/mtr/current-version.txt 自动确定当前版本。
  2. 验证 manifest、schema 和术语库。
  3. 若 outputs/omegat-mtr-full/omegat.project 不存在，调用现有 export_full() 生成 17 个 PO、1453 个单元及 OmegaT 配置。
  4. 若项目已存在，只验证结构并显示项目路径；绝不覆盖 project_save.tmx、target 或批注。
  5. 提示用户在 OmegaT 中打开/继续该项目。为避免安装路径和窗口控制问题，本阶段不自动驱动 OmegaT。

人工阶段：OmegaT

  1. 翻译、维护术语表、撰写句段批注。
  2. 完成本批审校后，执行“项目 → 创建已译文档”。这是唯一保留的人工衔接动作。

选项 2：完成审校并生成最终文档

验证 source/target/TMX→ 自动建议改动文件→ 差异报告→ 临时候选验证→ 一次确认→ 最小写回 YAML→ 测试 + 非阻塞术语审计→ 生成 dist + 登记进度

主体沿用当前 run_workflow()。唯一结构性调整是把持久的 outputs/omegat-candidates/<timestamp> 改成 Python 标准库 TemporaryDirectory；候选仅在预览与确认期间存在，完成、取消或报错后自动清理。

选项 3：查看审校进度

  1. 调用现有 calculate_status() 和 write_status_reports()。
  2. 在窗口中显示总数、已审未改、已审已改、失效、未审数量。
  3. 覆盖写入 outputs/review-status.json 与 outputs/review-status.md；不生成新目录。

6. 备选方案及取舍

方案优点缺点结论
保留现状，只改文档零代码改动首次准备与状态查看仍需长命令；候选继续累积不推荐
扩展现有审校助手为三选项菜单一个入口，最大复用，改动少翻译前后需分别运行同一个入口推荐
自动控制 OmegaT、自动点击创建已译文档表面上更像“一键”依赖安装路径、窗口状态和版本；容易覆盖未保存内容不采用
直接解析 project_save.tmx，跳过 target PO少一次 OmegaT 操作重复原文、替代译文和文件上下文映射更脆弱，失去稳定 msgctxt 校验不采用
新建 GUI 应用界面友好个人项目不值得承担框架与维护成本不采用

10. 验收标准

  1. 用户日常只需双击 审校助手.cmd，不需要输入路径或命令行参数。
  2. 同一入口能够安全准备项目、完成回写/构建、查看进度。
  3. 已有 OmegaT 工作绝不会被“准备项目”覆盖。
  4. 完成阶段仍只有一次应用确认；术语告警不阻塞。
  5. 成功后正式 YAML、dist/MTR.md、dist/rules.json 和审校台账相互一致。
  6. 候选验证目录不再累积；连续运行后 outputs 只保留当前项目和最新报告。
  7. 全部现有及新增测试通过。

11. 风险、失败模式与缓解

风险缓解
准备阶段覆盖已有 TMX/批注只在完整项目不存在时导出；目录存在但结构异常则停止并报告，不自动修复。
OmegaT 开着时清理或外部修改项目清理必须在进程关闭后执行；正式工作流不直接改 project_save.tmx。
测试失败时 YAML 已写入但 dist/台账未更新明确报告中间状态并允许修复后重跑；不做自动回滚，以免覆盖用户未提交的其他改动。Git diff 是恢复依据。
临时候选在崩溃后残留使用标准库 TemporaryDirectory；极端进程终止留下的系统临时目录不位于仓库。
清理误删当前工作只使用固定字面路径，执行前逐项验证绝对路径位于仓库且不包含 active project 核心文件。

12. 回滚与恢复

  • 工作流代码和文档通过 Git 回滚。
  • 正式翻译通过 Git diff/历史恢复；工具不执行 git reset。
  • 当前 OmegaT 项目保留 omegat/project_save.tmx.bak 作为最近恢复点。
  • 一次性删除的 pilot、probe 和 candidate 均可由现有导出器/验证器重建；不包含唯一翻译数据。
