1. 决策摘要

内容事实源

YAML，按章节拆分，只允许人工编辑这里；JSON 和 Markdown 均为可重建产物。

正文模型

section → group → block。group 保留官方段落边界；block 是按注解拆分的最小维护单位。

差异模型

先对完整 group 做官方原文 diff，再把变化投影到旧 block 边界；不直接拿 PDF 段落逐项匹配旧 block。

注解

每个 block 最多一条 extras，注解本身可包含多个 Markdown 段落；当前阶段长期冻结。

图片

YAML 引用仓库 PNG；构建时转为无换行 Base64 Data URI，直接写入最终 JSON/Markdown 的图片语法。

发布授权

机器人只创建更新 PR；人工合并是发布授权；合并到默认分支后自动构建和发布。

核心不变量：任何时候都能把同一 group 的英文 block 按规则拼回规范化官方段落；否则 YAML 无效，禁止发布。

2. 范围、非目标与权限边界

本设计覆盖

  • 官方 MTR PDF 的动态发现、下载、归档与版本判断。
  • PDF 到临时英文 AST 的规范化解析。
  • 旧 YAML 与新英文 AST 的 section/group/block 对齐。
  • 英文 diff、中文继承、冻结注解继承和冲突报告。
  • YAML Schema、ID 规则、图片 Base64 规则。
  • 单文件 JSON 和 Markdown 的确定性构建。
  • 定时 PR、PR 校验、合并后发布、测试和回滚。

当前明确不做

  • 自动翻译中文正文。
  • 自动更新英文注解或中文注解。
  • 保证任意 PDF 布局均可零配置解析。
  • 前端 Markdown 渲染器、Data URI 安全策略或 UI 改造。
  • 把生成的 JSON 当成人工编辑入口。
  • 在存在低置信度匹配或孤立注解时自动发布。

假设

  • 官方 MTR 的章节编号 1–10 与附录 A–F 总体稳定；结构变化仍须可被报告。
  • 现有英文/中文注解可视为冻结内容，只有其锚定正文发生结构冲突时需要人工处置。
  • 图片数量少且长期稳定，Base64 体积开销可接受。
  • 列表与表格可以作为 Markdown 字符串进入最终 JSON。
  • 人工合并 PR 即表示本次翻译校对完成，无需在每个 block 中保存 review 状态。

权限边界

定时工作流可以读取官方页面并向仓库创建分支和 PR，但不能绕过分支保护、自动合并或直接发布存在冲突的内容。设计阶段不修改实现代码、不下载或替换正式来源文件。

4. 当前状态与主要缺口

已有资产

  • 完整的旧 AMTR Markdown，可供人工迁移。
  • 一个可参考字段风格的双语规则 JSON。
  • 明确的人工校对和发布授权流程。
  • 已经冻结的 group/block、extras、Base64 决策。

缺口

  • 没有 YAML Schema、样例或构建器。
  • 没有官方 PDF 归档与来源索引。
  • 没有 PDF parser、reconciler 或 diff 报告。
  • 旧 Markdown 引用的图片文件不在当前工作区。
  • 没有 Git 仓库、CI、发布目标和分支保护配置。

6. YAML 内容模型

YAML 是唯一可编辑内容源。按章节拆分减少冲突和审阅噪声；manifest 决定顺序，不能依赖文件系统排序。

6.1 Manifest

schemaVersion: 1
document:
  id: mtr
  title:
    en: "Magic: The Gathering Tournament Rules"
    zh: "万智牌比赛规则"
  version: "20260227"
  effectiveDate: "2026-02-27"

files:
  - introduction.yaml
  - chapter-01.yaml
  - chapter-02.yaml
  - chapter-03.yaml
  - chapter-04.yaml
  - chapter-05.yaml
  - chapter-06.yaml
  - chapter-07.yaml
  - chapter-08.yaml
  - chapter-09.yaml
  - chapter-10.yaml
  - appendix-a.yaml
  - appendix-b.yaml
  - appendix-c.yaml
  - appendix-d.yaml
  - appendix-e.yaml
  - appendix-f.yaml

官方 URL、SHA-256 和获取时间不放进每条正文；它们由自动化维护在 sources/index.json。

6.2 章节文件

chapter:
  id: mtr-1
  chapter: "1."
  en: "Tournament Fundamentals"
  zh: "比赛基本要素"

sections:
  - id: mtr-1.1
    chapter: "1.1"
    en: "Tournament Types"
    zh: "比赛种类"
    groups:
      - id: mtr-1.1-g001
        type: paragraph
        blocks:
          - id: mtr-1.1-b001
            en: |-
              There are two types of sanctioned Magic tournaments: rated and casual.
            zh: |-
              万智牌认证赛事分为两种：积分赛和休闲赛。
            extras:
              - en: |-
                  First annotation paragraph.

                  Second annotation paragraph.
                zh: |-
                  注解第一段。

                  注解第二段。

          - id: mtr-1.1-b002
            en: |-
              Rated tournaments are further divided into two types...
            zh: |-
              积分赛又分为两种类型……

6.3 字段约束

对象必填字段约束
chapter / sectionid, chapter, en, zh自然章节号与稳定技术 ID 分离；标题不能为空。
groupid, type, blockstype 为 paragraph/list/table/image/markdown；至少一个 block。
文本 blockid, en, zh允许 Markdown；新内容候选阶段 zh 可为空，但 main 发布构建禁止为空。
extrasen, zh数组最多一个元素；字符串可包含多个 Markdown 段落。
图片 blockid, asset, alt.en, alt.zhasset 必须位于仓库 assets 根下；不允许 URL 或 Base64 写回 YAML。
未知字段—Schema 默认拒绝，避免拼写错误被静默忽略。

6.4 拼接规则与不变量

group 类型英文 block 间隔中文 block 间隔说明
paragraph单个空格空字符串注解拆分原则上只发生在完整句子边界。
list换行换行可按列表项拆 block；Markdown 标记保留在字符串中。
table换行换行通常整个表格只有一个 block。
markdown换行换行用于无法归入前三类的静态富文本。
image不拼接不拼接一个 group 通常一个图片 block。

仅在无法使用默认间隔的极少数边界允许 block 指定 joinAfter.en/zh；Schema 禁止 image 使用该字段。

7. ID 生命周期

ID 是持久状态，不是正文哈希，也不是实时顺序。正文变化、block 移动或在中间插入内容，都不能导致既有 ID 重编号。

格式

  • 章节：mtr-1.1、mtr-appendix-c。
  • group：mtr-1.1-g001。
  • block：mtr-1.1-b001。block 编号在 section 内单调分配，与 group 无绑定，允许 group 调整后仍保留。

分配规则

  1. 初始人工迁移按阅读顺序分配三位十进制序号。
  2. 后续新增永远使用当前 section 的最大编号 + 1，即使插入数组中部。
  3. 删除的 ID 永不复用；历史可由 Git 追踪。
  4. 语义连续的正文修改保留 block ID；真正新增内容获得新 ID。
  5. 拆分 block：主要延续部分保留原 ID，其余获得新 ID；必须人工确认。
  6. 合并 block：保留一个主 ID，其他 ID 进入报告，不自动选择。

8. PDF 发现、解析与规范化

8.1 发现与获取

  1. GET WPN 规则文档页面，定位标题精确匹配 “Magic: The Gathering Tournament Rules” 的下载链接。
  2. 限制目标主机为已批准的 Wizards 官方域名；跟随重定向后再次验证主机。
  3. 验证 HTTP 成功、Content-Type、%PDF- 文件头、合理体积上限。
  4. 计算 SHA-256。只有哈希变化才进入更新； ETag/Last-Modified 仅作记录。
  5. 解析首页 effective date，并与页面日期、文件名日期作一致性提示；首页日期是内容版本权威值。
  6. 原始 PDF 按 effective date + 哈希归档，禁止原地覆盖。

8.2 临时英文 AST

ParsedDocument
  effectiveDate
  sections[]
    chapter
    title
    groups[]
      type
      en
      sourcePages[]
      parseWarnings[]

临时 AST 不包含中文、注解或稳定 block ID，也不作为人工编辑格式。

8.3 规范化

  • 删除页眉、页脚、裸页码和目录页重复内容。
  • 合并视觉换行；修复跨行断词与软连字符。
  • Unicode NFC；规范化不可见空白，但不随意替换弯引号、商标符号或标点。
  • 识别章节标题、列表、表格和附录；跨页段落必须重新连接。
  • 保留原始页码范围，供报告定位；不写进人工正文 block。
  • 解析后必须检测 1–10 章、A–F 附录、effective date、文本覆盖率和异常空 section。

9. 两层对齐与差异算法

9.1 原则

旧 YAML 已按注解拆 block，而新 PDF 没有。更新时先按 group 拼回旧官方段落，再进行 group diff；只有 group 对齐后才投影旧 block 边界。

旧 YAML: [b001: Sentence A.] [b002: Sentence B.]
拼接后:  Sentence A. Sentence B.
新 PDF:  Sentence A. New sentence. Sentence B.

9.2 Group 匹配顺序

  1. 在相同 section 和相同 type 内进行有序匹配。
  2. 规范化文本完全相同：置信度 exact。
  3. 文本相似且前后邻居一致：置信度 high。
  4. 一对多或多对一候选：标记 split/merge，不自动提交最终映射。
  5. 低于阈值或候选并列：LOW_CONFIDENCE，阻止发布。

9.3 Block 边界投影

对旧完整 group 与新 group 做单词+标点 token diff，建立旧位置到新位置的映射：

变化处理ID注解
group 未变原样复用 YAML全部保留全部保留
修改完全位于一个 block 内更新该 block.en，继承旧 zh保留继承并列入人工校对报告
在两个 block 边界新增完整句子创建新 block，放在对应数组位置分配新 ID无 extras；zh 为空
修改跨越 block 边界RESEGMENT_REQUIRED不自动决定不得静默迁移
带注解 block 被完全删除ORPHANED_EXTRA历史保留，不进入候选正文必须人工确认处置
group 拆分/合并GROUP_SPLIT / GROUP_MERGE候选映射必须人工确认

9.4 双层报告

  • 官方变化报告：以完整 group 为单位，展示旧/新英文和词级 diff。
  • 翻译工作清单：以 block 为单位，列出 changed/added/deleted/resegment/orphan。

报告是 PR 产物，不写成 block 的 review 字段。人工编辑 YAML 后重新运行校验；当 YAML 拼接结果等于新 AST 且冲突消失，PR 才可合并。

10. 图片与 Base64 Data URI

10.1 YAML 表达

- id: mtr-10.4-g017
  type: image
  blocks:
    - id: mtr-10.4-b028
      asset: ../../../assets/playoff-bracket-8.png
      alt:
        en: "Eight-player playoff bracket"
        zh: "八人决胜轮对阵图"

10.2 构建契约

  1. 解析并归一化 asset 的绝对路径，确认仍位于仓库 assets/ 根内，防止路径穿越。
  2. 只允许显式白名单 MIME；首版允许 image/png。
  3. 验证 PNG 魔数，读取原始字节并使用 RFC 4648 标准 Base64。
  4. 保留 = padding；Base64 字符串不得换行或包含空白。
  5. 生成双语 Markdown：![alt](data:image/png;base64,...)。
  6. 英文和中文字段包含同一数据，允许重复体积；不在 YAML 内保存 Base64。
  7. 单文件 Markdown 同样内联 Data URI。
{
  "id": "mtr-10.4-b028",
  "en": "![Eight-player playoff bracket](data:image/png;base64,iVBORw0KGgo...)",
  "zh": "![八人决胜轮对阵图](data:image/png;base64,iVBORw0KGgo...)"
}
当前范围：保证 Data URI 被正确生成、可逆解码且等于源文件；前端 Markdown 渲染器是否允许 data: URL 暂不作为流水线阻塞条件。

11. 输出模型

11.1 最终 JSON（建议契约）

沿用 rules.json 的章节和双语字段习惯，引入 contents 表达 MTR 章节中的无编号正文。group 不进入最终产物。

{
  "version": "20260227",
  "intro": { "contents": [] },
  "main": [
    {
      "chapter": "1.",
      "en": "Tournament Fundamentals",
      "zh": "比赛基本要素",
      "subrules": [
        {
          "chapter": "1.1",
          "en": "Tournament Types",
          "zh": "比赛种类",
          "contents": [
            {
              "id": "mtr-1.1-b001",
              "en": "...",
              "zh": "...",
              "extras": [
                { "en": "...", "zh": "..." }
              ]
            }
          ]
        }
      ]
    }
  ],
  "appendices": []
}

精确的前端字段契约可在实现 builder 前调整，但中间模型必须无损映射到上述结构。extras 缺失表示无注解，不输出空数组。

11.2 Markdown

  • 目录和锚点由生成器统一生成，不人工维护。
  • 章节标题按 中文 + 英文 或最终模板输出；模板与内容分离。
  • block 依次输出英文、中文；extras 以引用块输出英文注解和中文注解。
  • 图片以 Base64 Data URI 内联；产物不得含相对图片路径。
  • 生成器固定 UTF-8、LF、末尾单换行与稳定键序。

11.3 确定性

任何时间戳、运行 ID、绝对路径、随机 UUID 都不得进入 dist。相同 Git 提交连续构建两次，JSON 与 Markdown 的 SHA-256 必须完全一致。

12. GitHub Actions 工作流

check-mtr.yml

定时 + workflow_dispatch。发现新哈希，归档 PDF、解析、对齐、生成候选 YAML 与报告，并创建/更新单一机器人 PR。

validate.yml

pull_request。执行 Schema、ID、group 重建、资源、冲突、测试和确定性构建；上传预览 artifact。

publish.yml

push main。重新从 YAML 构建，不复用不受信任 PR artifact；运行全套校验后发布到待确定目标。

PR 行为

  • 同一官方版本只维护一个机器人分支和 PR，重复运行幂等更新。
  • 无变化时零提交、零 PR。
  • 存在冲突时仍可创建用于人工处理的 PR，但 Required Check 保持失败。
  • PR 摘要列出来源 URL、effective date、PDF SHA-256、group 变化数、block 工作量和冲突。
  • 人工直接编辑该 PR 中的 YAML；每次提交重新生成报告和预览。

安全与配置

  • Actions 固定到提交 SHA；最小权限。PR 工作流默认只读，更新工作流仅需 contents/pull-requests write。
  • 下载 URL 允许域名白名单、体积上限、超时和有限重试。
  • PDF 作为不受信任输入；解析运行不执行嵌入对象或脚本。
  • 无需外部机密；GitHub 自带 token 足够。发布目标若需 token，使用 Environment Secret 和人工保护。
  • 使用 workflow concurrency，防止两个定时更新互相覆盖。

  • PyMuPDF：主文本抽取与页级定位；必要时 pdfplumber 专门处理表格，避免一开始双解析器全量复杂化。
  • ruamel.yaml：保持可读 YAML 和稳定输出；jsonschema 校验。
  • 标准库 hashlib/base64/difflib；只有实际质量不足时再引入 rapidfuzz。
  • pytest + snapshot/golden fixtures；ruff 做格式和静态检查。

当前目录不是 Git 仓库，因此上述结构应在正式仓库建立后落地。设计 HTML 暂存于 outputs。

Definition of Done

  • 相同 PDF 哈希不会产生提交或 PR。
  • 新 PDF 可归档，并带 effective date、URL 和 SHA-256。
  • Parser 能识别 1–10 章与 A–F 附录，异常时硬失败。
  • 未变化 group 原样继承全部 block、译文与注解。

16. 风险与缓解

风险影响缓解
官方页面结构变化无法发现 PDF 或误抓其他文档精确标题、域名白名单、多结果失败、workflow_dispatch 与告警。
PDF 抽取噪声虚假 diff、段落错配规范化、结构不变量、golden fixtures、置信度阈值、原始 PDF 永久归档。
模糊匹配误继承中文或注解挂到错误正文section 内有序匹配、邻居约束、跨边界冲突硬失败。
YAML 手工错误内容丢失或格式破坏严格 Schema、未知字段拒绝、PR checks、按章节拆文件。
冻结注解与新规则不一致发布的注解语义过时对应正文变化时始终列入工作清单；当前不自动修改，但人工可决定是否保留。
Base64 放大产物JSON 体积增加、diff 不可读Base64 只存在 dist；YAML 保留源 PNG；图片少且稳定。
渲染器过滤 Data URI前端图片不显示当前设计不阻塞；真正接入前增加 renderer 集成测试，必要时调整前端策略。
机器人 PR 权限过大供应链风险固定 Action SHA、最小权限、受保护 main、发布重新构建。

17. 首次迁移、兼容与回滚

首次迁移

  1. 冻结 YAML Schema v1，并完成五个代表性样例：1.1、1.6、10.4、附录 B、附录 C。
  2. 从官方对应版本 PDF 建立旧英文 group 基线；不能只信任旧 Markdown 的换行。
  3. 维护者逐章把旧译本复制到 block，并依据现有注解边界拆分。
  4. 每章完成后运行：Schema、ID、group 英文重建、资源和生成快照。
  5. 附录缺英文、旧表格格式异常和缺失图片作为显式迁移问题，不自动猜测。
  6. 全文迁移完成前，旧 AMTR_2025.md 保持只读参考，不删除。

Schema 演进

  • schemaVersion 只在中间格式发生不兼容变化时增加。
  • 每次升级提供显式迁移脚本和前后 golden；不在读取时悄悄兼容旧形态。
  • 最终 JSON 版本与 YAML Schema 版本分离，避免文档日期和格式版本混淆。

回滚

  • 内容回滚：revert 产生问题的合并提交，重新从旧 YAML 构建。
  • 发布回滚：重新发布上一个已知良好 dist；不得手工修补线上 JSON。
  • Parser 回滚：旧 PDF 和 sources index 保留，可用旧实现重放。
  • 机器人异常：暂停 schedule，保留 workflow_dispatch 与人工更新路径。
